# Flutter → Expo 이식 결정 기록

## 문제와 선택

| 발견한 문제                             | 선택한 해결                                         | 이유 / 남은 제약                          |
| --------------------------------------- | --------------------------------------------------- | ----------------------------------------- |
| 원본 홈 import가 실제 폴더와 다름       | 실제 widgets/data/asset 내용을 기준으로 화면 재구성 | 원본 실행 화면과 픽셀 비교는 못함         |
| 하단 목적지 4개, 라우트 branch 2개      | 네 탭 모두 파일 라우트 제공                         | 진료/마이페이지는 이번에 추가한 최소 화면 |
| 확인/결과 화면이 Placeholder            | 4단계 예약 흐름 완성                                | 실제 신청은 별도 서버 필요                |
| mock 조회가 800초 지연                  | 즉시 반환하는 메모리 데모와 HTTP 구현 분리          | 데모는 실제 진료시간/정원 아님            |
| 날짜 선택만 있고 시간 UI가 없음         | 30분 슬롯, 지난 시각/마감 비활성화                  | 서버는 독립적으로 운영 규칙 검증          |
| 진료 선택 정보 전달 없음                | Context에 진료/날짜/시간 보관                       | 앱 종료 후 입력 복구는 미구현             |
| 날짜 빠른 변경 시 비동기 결과 역전 가능 | AbortController와 취소 상태 확인                    | 로딩/실패/빈 결과/재시도 UI도 추가        |
| 예약 버튼 연타 / 타임아웃 재시도        | 동기 ref 잠금과 동일 요청 멱등 키                   | 최종 보장은 서버 트랜잭션/유일 제약 필요  |
| 기기 시간대에 따른 예약 날짜 오차       | 한국 날짜 경계와 UTC 달력 계산                      | 날짜 테스트로 경계값 확인                 |
| 원본 블로그 링크 중 `/123456` 임시값    | 해당 카드는 블로그 홈 연결로 명시                   | 다른 게시물 주소/일자는 원본 그대로       |
| 원본 빈 콜백들이 아무 반응 없음         | 준비 중 안내, 전화번호 설정 지원                    | 확인되지 않은 번호/운영정보를 만들지 않음 |

## 기술 선택

- 기본 fetch를 공통 client로 감싸 작은 앱에 불필요한 HTTP 의존성을 추가하지 않았습니다.
- Repository 인터페이스로 구현 교체 지점을 고정했습니다. 상태 없는 구현은 객체로 충분하여 불필요한 클래스 계층을 만들지 않았습니다.
- 공통 색상, 버튼, 화면, 로딩/실패 컴포넌트를 분리했습니다. 한 번만 쓰는 홈 스타일은 해당 화면 안에 두었습니다.
- Context는 소규모 예약 초안에 한정했습니다. 캐시가 없는 현재 조회 hook의 한계(탭 재마운트 시 재조회)를 받아들였습니다.
- 캐러셀은 화면 이탈/백그라운드에서 타이머 동작을 줄이고 cleanup으로 정리합니다. 성능 향상 수치는 측정하지 않았으며 정량 개선을 주장하지 않습니다.
- Expo SDK에 맞는 의존성 버전과 lockfile로 설치 재현성을 확보합니다. SDK 57 공식 표의 React Native/React 버전을 따릅니다.

## 면접·개발 기록에 남길 내용

이번 코드는 AI가 이식을 작성한 결과입니다. 직접 구현한 것처럼 설명하기보다, 다음 검증과 수정 과정을 본인이 수행하여 기록하세요.

1. 문제: 기존 Flutter UI를 학습 언어인 TypeScript 기반 앱으로 옮기되 NestJS 연결에 따른 화면 수정 범위를 줄이고 싶었다.
2. 설계: 화면은 Repository 계약만 알고, HTTP 및 데모 구현을 한 곳에서 교체한다.
3. 실패 재현: 날짜 A 응답을 늦추고 B를 먼저 선택하면 A 슬롯이 나타날 수 있다.
4. 해결: 요청 취소 및 늦은 결과 무시. 재현 조건을 자동 테스트에 남긴다.
5. 운영 경계: 버튼 비활성화만으로 중복예약은 해결되지 않는다. DB 트랜잭션, 정원, 멱등 키를 서버에서 검증해야 한다.
6. 증거: 테스트 명령/결과, 변경 커밋, 재현 절차, 실제 휴대폰 확인 결과를 PR에 추가한다.

이후 권장 커밋 단위: `feat: 실제 진료 과목 API 연결`, `test: 예약 충돌 응답 재현`, `fix: 서버 트랜잭션으로 정원 초과 방지`. 이번 변경에 없는 기능을 완료한 것처럼 기록하지 않습니다.

## 실제 기기에서 추가 확인

- Android 시스템 뒤로 가기와 iOS 스와이프 이동
- 작은 화면/글자 확대/키보드 표시 시 버튼 접근성
- 전화 앱, 블로그 외부 브라우저 열기
- 네이티브 SecureStore 저장/재실행/로그아웃
- 느린 네트워크·서버 401/409 및 실서버 DB 저장
- 실제 진료과목, 운영시간, 원장 소개 이미지, 게시물 확인

웹 번들 성공은 네이티브 바이너리 빌드나 스토어 출시 검증을 대신하지 않습니다.
